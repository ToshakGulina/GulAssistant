# Тестовый стенд: отладка на своём ПК, потом Acer

Задача: **отлаживать на мощном ПК, но в условиях, максимально близких к Acer**,
а потом перенести уже проверенную сборку на неттоп одной командой.

Поэтому стенд — это не «облегчённая версия» и не браузерный микрофон, а тот же
самый Debian, тот же ALSA, тот же Vosk, тот же TTS и тот же код. Отличие только
в железе (и в наличии рабочего стола с браузером).

```
   Ваш ПК (7800X3D, 5070 Ti)                    Acer R3700 (D525, 4 ГБ)
   ┌──────────────────────────┐                ┌──────────────────────────┐
   │ Debian 13 + XFCE         │   rsync/ssh    │ Debian 13, без графики   │
   │ тот же GulAssistant      │ ──────────────▶│ та же сборка, та же служба│
   │ реальный микрофон/колонка│                │ реальный микрофон/колонка│
   │ Firefox + веб-интерфейс  │                │ веб-интерфейс по сети     │
   └──────────────────────────┘                └──────────────────────────┘
```

---

## 1. Куда ставить Debian

У вас есть отдельный HDD на 1 ТБ — это идеальный вариант: **Debian на второй
диск, Windows не трогаем**. Никакого разбиения основного SSD и риска для
загрузчика.

### Вариант A (рекомендую): физически отключить диск Windows

Самый безопасный способ, чтобы установщик Debian точно не тронул Windows:

1. Выключите ПК, **отключите SATA-кабель питания/данных от диска с Windows**
   (или отключите M.2, если Windows там).
2. Оставьте только HDD на 1 ТБ.
3. Установите Debian (шаг 2). Загрузчик GRUB встанет на этот же диск.
4. Выключите ПК, подключите диск Windows обратно.
5. В UEFI выберите загрузку с диска Debian (или через boot-menu F8/F11/F12).
6. Один раз загрузитесь в Debian и выполните `sudo update-grub` — появится
   пункт «Windows Boot Manager».

Плюс: два диска полностью независимы. Хотите вернуть всё как было — отключили
диск Debian, и Windows грузится как раньше.

### Вариант B: оба диска подключены

Можно, но требует аккуратности в ручной разметке:

- **Fast Startup** в Windows выключить: «Панель управления → Электропитание →
  Действия кнопок питания → снять „Включить быстрый запуск“».
- Если включён **BitLocker** — приостановить (`manage-bde -protectors -disable C: -RebootCount 1`)
  или сохранить ключ восстановления. Debian его не сломает, но после смены
  загрузчика Windows может попросить ключ.
- В установщике выбрать **ручной режим** и создать разделы **только на /dev/sdb**
  (ваш HDD): ESP 512 МБ, `/` — остальное (ext4), swap 2–4 ГБ по желанию.
- На шаге «Установить загрузчик GRUB» явно указать **/dev/sdb**, а не диск с
  Windows.
- После установки — загружаться с нужного диска через boot-menu.

Если сомневаетесь — делайте вариант A. Потерять Windows из-за неверной разметки
обидно, а отключить два кабеля — две минуты.

### Что создавать при установке

| Параметр | Значение |
|---|---|
| Дистрибутив | Debian 13 (trixie) netinst amd64, или 12 (bookworm) |
| Имя машины | `gul-test` (у Acer будет `gul`) |
| Пользователь | ваш обычный, не root |
| Разметка | весь диск HDD, ext4, swap 2–4 ГБ |
| Рабочий стол | **XFCE** (лёгкий, ближе всего к «без графики» по поведению) |
| SSH-сервер | да |
| Стандартные утилиты | да |
| Обновления | security |

XFCE + Firefox на 7800X3D — это ~600 МБ RAM и почти ноль CPU. На поведение
ассистента не влияет, зато даёт браузер и удобный терминал. Сам Гуль остаётся
консольным: тот же процесс, те же потоки, тот же ALSA.

> Почему не WSL2: звук в WSL идёт через прослойку, `arecord`/`aplay` ведут себя
> иначе, а PipeWire-устройства видны не так, как на Acer. Для «максимально
> близких условий» нужен настоящий Debian на реальном железе.
>
> Почему не виртуалка: та же причина плюс USB-микрофон придётся пробрасывать,
> а задержки станут нерепрезентативными.

## 2. Установка Debian

1. Скачайте **debian-13.x-amd64-netinst.iso** с debian.org.
2. Запишите на флешку (Rufus в Windows, `dd` в Linux).
3. Загрузитесь с флешки (F8/F11/F12 при старте).
4. Установщик: язык, раскладка, hostname `gul-test`, пользователь, диск, XFCE.
5. Перезагрузка, вход в XFCE.

Первичная настройка:

```bash
sudo apt update && sudo apt full-upgrade -y
sudo apt install -y sudo curl ca-certificates git
```

### 5070 Ti: драйвер не нужен

Для ассистента GPU не используется вообще. Открытый `nouveau` нормально тянет
рабочий стол и Firefox. Проприетарный драйвер NVIDIA ставьте только если он
нужен вам для других задач — на Гуля это не влияет.

Не устанавливайте CUDA/onnxruntime-gpu «на всякий случай»: это лишние гигабайты
и другой набор библиотек, чем на Acer. Стенд должен повторять Acer, а не
отличаться от него.

### Звук на рабочем столе: PipeWire

На Debian с XFCE звуком управляет PipeWire, но ALSA-программы (`arecord`,
`aplay`, Vosk, mpv) работают через слой `pipewire-alsa` — для Гуля это
прозрачно. Скрипт установки ставит `pipewire-alsa`, `wireplumber`, `pavucontrol`.

Проверьте, что микрофон виден:

```bash
arecord -l
wpctl status        # PipeWire: Sources / Sinks
pavucontrol         # вкладка Input Devices: выбрать микрофон и уровень
```

Если `arecord -D default` не открывает устройство, попробуйте:

```bash
arecord -D plughw:1,0 -f S16_LE -r 16000 -c 1 -d 5 /tmp/test.wav
aplay /tmp/test.wav
```

и пропишите рабочее устройство в `config.yaml → audio.input_device`.
На Acer, скорее всего, будет тот же `default` или `plughw:1,0` — но проверять
надо там, устройства нумеруются по-разному.

## 3. Установка Гуля на стенд

```bash
git clone https://github.com/ToshakGulina/GulAssistant.git
cd GulAssistant
bash scripts/install_testbox.sh
```

Скрипт поставит:

- Python, ALSA, `libasound2-plugins`, ffmpeg, mpv, espeak-ng;
- XFCE, Firefox ESR, PipeWire (если ещё нет);
- RHVoice, если он есть в репозитории;
- venv и зависимости, модель Vosk;
- `config.yaml` и `.env`;
- пользователя в группы `audio`/`pipewire`.

Служба автозапуска **не** ставится — на стенде вы будете запускать вручную,
чтобы правки кода сразу вступали в силу. Добавить службу можно позже:

```bash
bash scripts/install_testbox.sh --service
```

После установки **перезайдите в систему** (группы применяются при входе).

```bash
nano .env      # GIGACHAT_CLIENT_ID / GIGACHAT_CLIENT_SECRET
```

Ключ GigaChat бесплатный для физлица:
https://developers.sber.ru/portal/products/gigachat-api

## 4. Проверка: те же команды, что будут на Acer

Именно этот набор прогоняйте на обеих машинах — так вы ловите различия, пока
неттоп ещё не переехал на кухню.

```bash
.venv/bin/python run.py --doctor          # общая диагностика
.venv/bin/python run.py --mic-test 4      # микрофон: уровень, шум, речь
.venv/bin/python run.py --speaker-test    # колонка: beep + настоящий TTS
.venv/bin/python run.py --bench           # TTS, LLM, Vosk
.venv/bin/python run.py                   # голос + веб
```

`--doctor` проверяет: CPU-флаги, RAM, systemd, arecord/aplay/ffplay/mpv, ALSA-
устройства, звуковой сервер (PipeWire/чистый ALSA), модель Vosk, пакет `vosk`,
слова активации, все TTS-движки по порядку, ключи и **реальный запрос** к
первому доступному мозгу, адрес веба, предупреждения конфига.

`--mic-test` — самое полезное на стенде. Он печатает:

```
Уровень: RMS 412, пик 3211, шум 96, порог речи 210
Речь в 62% кадров, клиппинг 0.0%
✔ Микрофон работает, речь уверенно выше шума.
  Подсказка: если ассистент ловит шум, поставьте audio.vad_threshold: 211
```

Если пишет «микрофон молчит» — это не баг Гуля, а mute/неверный вход/нулевой
Gain в `alsamixer`. Чинится до первого запуска, а не после.

`--speaker-test` идёт тем же путём, что и живой ответ: `AudioPlayer`
(`aplay`/`ffplay`/`mpv`) + `Speaker` (Edge → Piper → RHVoice → espeak). В конце
он честно скажет, какой движок сработал и за сколько миллисекунд.

Дальше — веб-интерфейс: откройте `http://127.0.0.1:8787` в Firefox. Это тот же
интерфейс, что будете открывать с телефона на Acer.

## 5. Приблизить условия Acer (по желанию)

Мощный ПК скрывает проблемы, которые вылезут на Atom. Ограничьте себя:

```bash
# 2 потока и ~20% CPU — примерно как D525
bash scripts/emulate_acer.sh .venv/bin/python run.py --web

# жёстче (как совсем загруженный неттоп)
bash scripts/emulate_acer.sh --quota 12 .venv/bin/python run.py

# добавить сетевую задержку (действует на интерфейс, нужен root)
bash scripts/emulate_acer.sh --net enp4s0 .venv/bin/python run.py --web
```

Скрипт использует `systemd-run` (cgroups v2) или `cpulimit`/`taskset`.
Смысл — проверить не скорость, а **поведение**: не отваливается ли Vosk, не
растёт ли память, не появляются ли гонки при медленном CPU, успевает ли
потоковая озвучка.

Чего этот скрипт не делает: не убирает AVX/SSE4. Пакеты, которые на D525 упадут
с `Illegal instruction`, здесь не упадут — это проверится только на Acer.
Поэтому в проекте нет обязательных зависимостей с AVX (torch, onnxruntime):
`vosk`, `edge-tts`, `paho-mqtt`, `requests` — чистые или с базовыми сборками.

## 6. Что проверять до переезда

| Проверка | Ожидание |
|---|---|
| `--doctor` | критических проблем нет; мозг отвечает |
| `--mic-test 4` | речь > 20% кадров, клиппинг 0% |
| `--speaker-test` | звук есть, движок назван |
| `--bench` | TTS и LLM выдают числа, Vosk грузится |
| «Привет, Гуль» | beep, затем ответ (голосом) |
| «Поставь таймер на 1 минуту» | сработает через минуту, переживёт перезапуск |
| «Погода» | ответ за < 1.5 с (кэш — < 100 мс) |
| «Расскажи что-нибудь» | первый звук 1.5–3.5 с |
| Перезагрузка | данные (заметки, таймеры, память) на месте |
| `curl /api/status` | провайдеры, метрики, 16 скиллов |

Таймеры, заметки и память переживают рестарт — это стоит проверить один раз
до переезда, чтобы потом не искать баг на кухне.

## 7. Перенос на Acer

На Acer должен быть установлен Debian (см. `docs/HARDWARE.md`) и настроен SSH:

```bash
ssh-copy-id gul@acer.local       # один раз, со стенда
```

Дальше — одной командой:

```bash
bash scripts/deploy_to_acer.sh --host gul@acer.local --config --env
```

Что произойдёт:

1. `rsync` кода (без `.venv`, `models`, `data`);
2. копирование проверенных `config.yaml` и `.env` (флаги `--config`, `--env`);
3. на Acer запустится `setup_debian.sh`: пакеты, venv, модель Vosk, служба;
4. `systemctl restart gul` и `--doctor` прямо на неттопе.

Данные (заметки, память, таймеры) переносятся флагом `--data`, если хотите
сохранить накопленное на стенде. Обычно не нужно: на Acer лучше начать с чистых.

Перед первым запуском на Acer проверьте там то же самое:

```bash
ssh gul@acer.local
cd ~/GulAssistant
.venv/bin/python run.py --doctor
.venv/bin/python run.py --mic-test 4
.venv/bin/python run.py --speaker-test
.venv/bin/python run.py --bench
```

Разница в цифрах — нормально (Atom в 5–15 раз медленнее). Разница в
«работает / не работает» — это баг, который надо починить.

## 8. Если что-то пошло не так

| Симптом | Где смотреть |
|---|---|
| `arecord` не видит микрофон | `arecord -l`, `wpctl status`, `pavucontrol`, группа `audio` |
| Микрофон есть, но тишина | `alsamixer` → F4 → Capture, снять mute, Gain |
| Нет звука | `--speaker-test`, затем `aplay /usr/share/sounds/alsa/Noise.wav` |
| Vosk не грузится | `--doctor`, папка `models/`, `bash scripts/download_models.sh` |
| LLM не отвечает | `--doctor` делает реальный запрос и печатает ошибку |
| Порт занят | `ss -ltnp \| grep 8787`; остановите старый процесс или `--port 8788` |
| После переезда служба не стартует | `ssh acer 'journalctl -u gul -n 100 --no-pager'` |
| Не грузится Windows после установки | В UEFI выбрать Windows Boot Manager; диск Debian можно отключить |

## 9. Почему такой стенд — правильный

- **Тот же код и те же зависимости.** Никаких «на ПК сработало, на Acer нет».
- **Тот же звуковой путь.** `arecord`/`aplay`, реальный микрофон, реальный Vosk.
- **Тот же Debian и systemd.** Служба, автозапуск, логи — как на неттопе.
- **Браузер только для удобства.** Он не участвует в голосовом цикле.
- **GPU не используется.** 5070 Ti не влияет на Гуля — и это правильно, иначе
  стенд перестал бы быть стендом.

Единственное честное расхождение — скорость. Именно поэтому есть
`emulate_acer.sh` и обязательный финальный прогон проверок уже на Acer.
