## Модули

| Модуль | Ответственность |
|---|---|
| `run.py` | CLI, режимы, сигналы, логирование, systemd-точка входа |
| `gul/config.py` | YAML + `.env`, значения по умолчанию, предупреждения |
| `gul/assistant.py` | склейка компонентов, системный промпт, история, ответы, метрики |
| `gul/voice.py` | цикл прослушивания, запись команды, barge-in |
| `gul/audio.py` | arecord/aplay, VAD, WAV, beep, список ALSA-устройств |
| `gul/stt.py` | Vosk-модель (одна на процесс), wake-word, команда, stop-words, облачный резерв |
| `gul/tts.py` | 4 движка, выбор по доступности, потоковая озвучка, фолбэк |
| `gul/llm/providers.py` | конкретные HTTP-клиенты и SSE-парсинг |
| `gul/llm/router.py` | порядок провайдеров, cooldown, health, автопереключение |
| `gul/skills/*` | быстрые команды и их данные |
| `gul/skills/timers.py` | фоновый планировщик таймеров/будильников/напоминаний |
| `gul/server.py` | HTTP API, NDJSON-стриминг, SSE, статика |
| `web/` | интерфейс без сборки: HTML + CSS + vanilla JS |

## Поток голосового ответа

1. `Microphone` запускает `arecord` и отдаёт сырой PCM 16 кГц моно кусками по 125 мс.
2. `WakeWordDetector.feed()` прогоняет звук через Vosk.
   - В режиме `grammar` распознаются только слова активации — минимум CPU.
   - В режиме `auto` при старте проверяется, есть ли все слова в словаре модели;
     если нет — включается полное распознавание (для имён вроде «Гуль»).
   - Срабатывание ловится по `PartialResult`, не дожидаясь тишины.
3. Звучит beep, `CommandSTT` пишет команду, VAD и partial-результаты определяют
   конец фразы (0.8 с тишины или 12 с максимум).
4. `Assistant.answer_voice()`:
   - нормализует текст и убирает слово активации;
   - `SkillRegistry.dispatch()` перебирает навыки по приоритету;
   - если навык найден — отвечает за миллисекунды и озвучивает;
   - иначе запускает `LLMRouter.stream()` и `Speaker.say_stream()`.
5. `Speaker` режет поток на предложения, синтезирует следующее предложение,
   пока играет текущее, и сразу отдаёт звук в колонку.
6. Пока играет ответ, `StopWordDetector` слушает только «стоп/тише/хватит»
   и может прервать воспроизведение.

## Поток веб-ответа

`POST /api/chat` → `Assistant.respond_stream()` → построчный NDJSON:

```json
{"type":"state","state":"thinking"}
{"type":"delta","text":"Сейчас "}
{"type":"delta","text":"в Москве "}
{"type":"done","source":"llm","provider":"gigachat","total_ms":2140,"first_token_ms":830}
```

- `skill` — готовый ответ навыка;
- `delta` — кусок текста LLM;
- `state` — «thinking/speaking/listening»;
- `done` — финал с метриками;
- `error` — ошибка, если что-то пошло совсем не так.

`GET /api/events` — SSE для таймеров и служебных событий. `GET /api/status` —
CPU, RAM, провайдеры, TTS, метрики, список умений.

## LLM-роутер

Порядок из `brain.order`. Для каждого провайдера:

1. `available()` — есть ли ключ/URL.
2. Пропуск, если он в cooldown (90 с после ошибки).
3. Запрос стрима. Если ошибка **до первого токена** — следующий провайдер.
4. Если ошибка **после первого токена** — не начинаем ответ заново, просто
   аккуратно завершаем фразу.
5. Успех — записываем latency, счётчик, статус для UI.

Так GigaChat с исчерпанным лимитом или Groq с 403 не ломают разговор: следующий
мозг подхватывает за миллисекунды. Если не работает вообще ничего, ассистент
честно говорит об этом и предлагает проверить VPN/ключи.

**GigaChat:** OAuth `POST /api/v2/oauth` с `RqUID`, `scope=GIGACHAT_API_PERS`,
кэш токена в `data/.gigachat_token.json`, `verify_ssl=false` из-за фирменного
сертификата. Токен обновляется за 90 с до истечения и один раз при 401.

**Groq / Cloudflare / generic:** OpenAI-совместимый `/chat/completions`.
Если провайдер не умеет `stream`, автоматически повторяем без стрима.

## TTS-конвейер

```
токены LLM ─▶ SentenceBuffer ─▶ предложение ─▶ синтез (ThreadPoolExecutor 1)
                                                   │
                                                   ▼
                                            AudioPlayer.play_file()  ← блокирует до конца фразы
```

- Пока играет предложение N, в фоне синтезируется N+1 — первый звук не ждёт
  весь ответ.
- Движки перебираются по `tts.engines`; упавший движок отключается на 120 с.
- Edge TTS отдаёт MP3, играем через ffplay/mpv; локальные движки — WAV через aplay.
- Временные файлы чистятся, хранится не больше 40.

## Потоки и память

- Главный поток — голосовой цикл (если включён).
- `timers` — планировщик, проверка каждые 0.5 с.
- `web` — `ThreadingHTTPServer`, по потоку на запрос/SSE.
- `tts` — один рабочий поток синтеза.
- `prewarm` — фоновый прогрев погоды при старте.
- Модель Vosk одна на процесс (`VoskModel._cache`), ~200 МБ RAM.
- `arecord`/`aplay`/`mpv` — отдельные процессы, минимум Python-памяти.
- История диалога ограничена `max_history_turns` (по умолчанию 8 пар).

Ориентировочное потребление на R3700: Python 120–180 МБ, Vosk 200–250 МБ,
mpv 20–40 МБ, система 250–350 МБ. Итого ~0.8–1.0 ГБ из 4 ГБ — есть запас.

## Безопасность и приватность

- По умолчанию **аудио не покидает устройство**: облачный STT выключен.
- В облако уходит только текст вопроса — и только если нужен ответ LLM.
- Ключи хранятся в `.env`, не попадают в Git и логи.
- Веб-интерфейс можно закрыть токеном (`web.token`) — тогда API требует
  заголовок `X-Gul-Token` или `?token=`.
- `system.allow_shutdown` по умолчанию `false`: голосом нельзя выключить неттоп.
- MQTT-пароль и токены не логируются; ошибки обрезаются.
- Для доступа из интернета используйте reverse proxy с HTTPS (Caddy/Nginx)
  и обязательно задайте токен.

## Расширение

Новый навык — класс с `name`, `priority`, `handle()`. Возвращает `SkillResult`:

```python
SkillResult(
    text="Полный текст для чата",
    speak="Короткая версия для озвучки",   # необязательно
    needs_llm="Промпт для нейросети",       # необязательно
    stop_audio=False,                       # остановить музыку/речь
)
```

Доступ к конфигу и сервисам — через `SkillContext`: `cfg`, `llm`, `timers`,
`notes`, `memory`, `music`, `speaker`, `now`.
